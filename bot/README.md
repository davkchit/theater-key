# Бот театра «Ключ» и заявки сайта

Один небольшой сервис (`bot/server/`) делает три вещи:

- **Telegram-бот** «кот театра»: отвечает на вопросы по данным сайта и записывает
  на курсы и на «Направления» (подготовительные группы, фестиваль, квесты,
  карнавальные ночи, рассылку);
- **отвечает в окне чата на сайте** (кот в углу, `POST /api/chat`): тот же бот, те же ответы и та же запись, что в Telegram;
- **принимает заявки с форм сайта** (`POST /api/lead`);
- **присылает заявки** на почту театра и карточками со статусами в группу
  администраторов, хранит их в базе на сервере и выгружает для Excel.

Главный принцип: **модель разговаривает, код записывает.** Нейросеть только
отвечает на вопросы. Имена, телефоны, шаги анкеты, статусы и отправку заявок
ведёт обычный код, поэтому ошибка модели в худшем случае даёт ответ «уточнит
администратор», а не мусор в заявках. Где слова модели и действия кода могут
разойтись («форма откроется», а формы нет), код сам проверяет ответ и
добавляет кнопку.

Раньше бот работал на n8n; с сентября 2026 это собственный сервис с той же
логикой (`bot/core/lib.js` не менялся при переезде). Файлы n8n
(`workflows/`, `scripts/build-workflow.mjs`, `n8n-local.mjs`, `poll-telegram.mjs`,
`serve-public.mjs`, `e2e-local.mjs`) остались до переезда на VPS и будут удалены.

## Что где лежит

| Путь | Что это |
|---|---|
| `core/lib.js` | Вся логика бота: кнопки, анкеты, лимиты, промт, разбор ответа модели, фильтры |
| `core/faq.md` | Справка, которой нет на сайте, и список того, на что бот сам не отвечает |
| `core/knowledge.mjs` | Собирает знание бота из данных сайта (`src/content/*.json`) |
| `core/llm.mjs` | Вызов модели для скриптов; провайдер задаётся тремя настройками |
| `server/index.mjs` | Запуск: чтение Telegram, HTTP (`/api/lead`, `/api/event`, `/health`), почта |
| `server/turn.mjs` | Одно сообщение от начала до конца: логика → модель → база → Telegram |
| `server/webchat.mjs` | Чат на сайте: сообщение из окна подаётся боту как из Telegram, ответ возвращается окну |
| `server/site.mjs` | Заявки с сайта: проверка, защита от спама, запись, письмо, карточка |
| `server/mail.mjs` | Письма о заявках: очередь в базе, повторы при сбоях |
| `server/store.mjs` | База SQLite: диалоги, заявки, очередь писем, вопросы без ответа |
| `server/export-leads.mjs` | Выгрузка заявок в CSV для Excel |
| `server/test.mjs` | 26 проверок сервиса без сети и без модели |
| `eval/cases.json` | 83 проверочных диалога для живой модели |
| `scripts/eval.mjs` | Прогон этих диалогов, счёт и сравнение с прошлым прогоном |
| `DEPLOY.md` | Как поставить на VPS |
| `env.example` | Все настройки с пояснениями |

## Запуск на своём компьютере

```
cp bot/env.example .env.bot     # и заполнить: токен бота, ключ модели
npm run knowledge               # собрать знание из данных сайта
npm run bot                     # бот: читает Telegram, слушает 127.0.0.1:8787
npm run dev                     # в другом окне: сайт, его формы шлют заявки боту
```

Одновременно может работать только одна копия бота: вторая получит от Telegram
«конфликт» и напишет об этом в лог. На Windows останавливать через Ctrl+C
в окне, где бот запущен.

Группа администраторов: создать группу, добавить туда бота, написать `/id`,
вписать число в `ADMIN_CHAT_ID`, перезапустить бота.

## Откуда бот берёт знание

```
администратор правит данные в админке сайта (/admin)
        ↓  коммит в GitHub, пересборка сайта
npm run build → public/knowledge.json   (той же сборкой, что и страницы)
        ↓  раз в 10 минут
бот
```

Бот не может знать ничего, чего не показывает сайт. Если знание не удалось
скачать, бот отвечает по последней хорошей копии и раз в 6 часов сообщает об
этом в группу администраторов.

**Афиша в промте — только нужная часть.** Модель всегда видит ближайшие 4 недели,
плюс показы за период, о котором спросили: месяц, дату, «выходные», «на этой
неделе», день недели. Период вычисляет код, модель ничего не считает. У каждого
спектакля в репертуаре перечислены все его даты. Промт около 4,2 тыс. токенов.

**Направления** (`src/content/directions.json`, раздел «Направления» в админке):
всё, на что можно записаться кроме курсов. У каждого свои вопросы анкеты,
переключатель «заявки открыты» и даты показа. Бот и сайт читают один и тот же
файл: добавленное в админке сразу можно забронировать и на сайте, и в чате.

**Запасной режим — документы театра** (`bot/docs/*.docx`, `KNOWLEDGE_SOURCE=docs`):
если театр будет присылать план сезона Word-файлом. Код: `core/docs.mjs`.
Папка `bot/docs/` не коммитится: репозиторий публичный.

## Заявки

Заявки из бота и с сайта лежат в одной таблице `leads` в `bot/data/kluch.sqlite`
(на сервере, в России). По каждой:

- **карточка в группе администраторов** с кнопками «Позвонили», «Не дозвонились»,
  «Записан»; статус сохраняется в базе;
- **письмо на почту** (новая, «ждёт звонка», дополнение, отмена). Письмо встаёт
  в очередь в той же транзакции, что и заявка, и уходит с повторами до суток:
  упавшая почта задерживает письмо, но не теряет его;
- **раз в неделю** (понедельник, 9:00 МСК) выгрузка за прошлую неделю письмом;
- **в любой момент:** `npm run leads` → `bot/data/заявки-ГГГГ-ММ-ДД.csv`
  (`-- --from=2026-09-01` с даты). Файл открывается в Excel как есть.

Защита заявок с сайта: только известные формы, только с согласием на обработку
данных, скрытое поле от роботов, не больше 6 заявок в час с адреса и 300 в день
на всех, только со своего сайта.

## Какая модель отвечает

Провайдер — три настройки, а не три куска кода: адрес, способ подписи, имя
модели. Яндекс, Groq и почти все остальные понимают один формат (OpenAI-совместимый).

| | Для чего | Настройки |
|---|---|---|
| Groq | бесплатные тесты | `LLM_BASE=https://api.groq.com/openai/v1`, `LLM_AUTH=Bearer`, `LLM_MODEL=openai/gpt-oss-120b` |
| Yandex AI Studio | прод, в России | `LLM_BASE=https://llm.api.cloud.yandex.net/v1`, `LLM_AUTH=Api-Key`, `LLM_MODEL=gpt://<папка>/gpt-oss-120b/latest` |

Для прода выбран **gpt-oss-120b в Yandex AI Studio**: та же модель, что прошла
проверки на Groq, и в 3–4 раза дешевле YandexGPT Pro (около 2 ₽ за ответ).

Несколько ключей: `LLM_KEY`, `LLM_KEY_2` … `LLM_KEY_9`. Когда у ключа кончается
дневной лимит, бот переходит на следующий и помнит, до какого времени тот
исчерпан. Минутный лимит пережидает на том же ключе. `EVAL_LLM_KEY` — отдельный
ключ для проверочных прогонов, чтобы они не съедали лимит бота.

## Проверить, не стало ли хуже

```
npm run bot:test                        # сервис: 22 проверки, без сети, секунды
node bot/scripts/test-flows.mjs         # сценарии логики, без модели
node bot/scripts/eval.mjs --dry         # проверочные диалоги без модели
npm run bot:eval -- --ids=a,b,c         # выбранные диалоги на живой модели
npm run bot:eval -- --save=before       # полный прогон с сохранением
npm run bot:eval -- --diff=before       # что починилось, что сломалось
```

**Каждый пойманный баг должен стать кейсом** в `eval/cases.json`, иначе он вернётся.
Некоторые правила проверяются в каждом кейсе (`forbidden`): бот не пишет, что
не принимает заявки, не отправляет «на сайт», не обещает форму без кнопки, не
называет спектакль «без возрастных ограничений», если возраст не указан.

## Парсер намерений

Перед ответом отдельный короткий вызов модели размечает сообщение: намерение
(вопрос, запись, отмена, жалоба…), просит ли человек *сделать* или только
*спрашивает*, возраст, спектакль. Действие (открыть анкету, отменить заявку)
выполняется только на явную просьбу; на вопрос бот отвечает и даёт кнопку.
Если парсер недоступен, работают запасные правила по словам.

```
node bot/scripts/parse.mjs "хочу записать дочку 7 лет" "а что в субботу?"
node bot/scripts/parse.mjs --set        # размеченный набор со счётом
```

## Защита и лимиты

- Модель не видит персональных данных: имена и телефоны ведёт код.
- Лимиты: 40 обращений к модели в день и 8 в минуту на чат, 150 в день на всех.
  Дальше бот отвечает кнопками и сообщает в группу.
- Сообщения длиннее 500 символов обрезаются.
- Сообщения одного чата обрабатываются строго по очереди.
- Секреты только в `.env.bot`: он не попадает ни в git, ни в Docker-образы.
- Сбои модели, знания и почты пишутся в `bot/data/bot.log` и сообщаются в группу.

## Известные ограничения

- Голосовые не распознаются.
- Цены билетов, скидки, возврат, парковка: театр не подтвердил, бот отвечает
  «уточнит администратор» (список в `core/faq.md`, раздел `[!limits]`).
- Правка в админке появляется на сайте после пересборки (`./deploy.sh` на сервере).
