# Как устроен проект

Подробности для разработчика. Короткое описание проекта: [README](../README.md). Бот описан отдельно в [bot/README.md](../bot/README.md), выкладка админки в [deploy/cms/README.md](../deploy/cms/README.md), установка бота в [bot/DEPLOY.md](../bot/DEPLOY.md).

## Части системы

| Часть | Где код | Где работает |
|---|---|---|
| Сайт | `src/`, `public/`, `assets/` | статика в `/opt/kluch/site`, отдаёт Caddy |
| Пререндер и SEO | `scripts/prerender.mjs`, `src/seo/` | при каждой сборке |
| Админка | `public/admin/config.yml`, `deploy/cms/` | `decap-server` (git-режим) на `127.0.0.1:8081` |
| Синхронизация с Билетоном | `bot/core/bileton.mjs`, `deploy/cms/sync-bileton.mjs` | `kluch-bileton.timer`, каждый час в :07 |
| Бот, чат, заявки | `bot/` | `kluch-bot.service` на `127.0.0.1:8787` |

Все они живут на одном VPS в России (Ubuntu 24.04, 1 ядро, 1 ГБ памяти), рядом с другим проектом. Поэтому у сборки и бота жёсткие лимиты памяти в systemd: сборка до 450 МБ (в пике берёт около 270 МБ), бот до 200 МБ.

## Сайт

React 19, TypeScript (strict), Vite 8, Tailwind CSS 4, Motion для анимаций, React Router 7. Формы на React Hook Form и Zod.

```
src/
  pages/          страница на каждый адрес; *V2: текущий дизайн, без V2: первая версия
  components/
    home2/        шапка, подвал, первый экран, бумага с рваными краями (paper.tsx)
    afisha/  repertoire/  courses/  team/  about/  contacts/  directions/
    mascot/       кот и окно чата
    tickets/      окно Билетона поверх сайта
    reviews/      просьба оставить отзыв после спектакля
    layout/  ui/
  content/        весь контент в JSON, его правит админка
  data/           читают JSON из content/ и отдают компонентам с типами
  seo/            заголовки, описания, schema.org, рендер на сервере для пререндера
  lib/            даты по-русски, типограф, рваные края (torn.ts)
  routes.tsx      список адресов, общий для браузера и пререндера
  router.tsx      выбор роутера и перенаправление старых ссылок /#/...
assets/           логотип, иконки, декор: то, что театр не меняет
public/uploads/   фото, которые загружает админка
```

Контент не зашит в компоненты. Всё, что может поменять театр, лежит в `src/content/*.json`, а файлы в `src/data/` только читают его и приводят к типам. Чтобы поменять текст или фото, код трогать не нужно.

### Пререндер и SEO

После `vite build` скрипт `scripts/prerender.mjs` собирает `src/seo/build.ts` отдельной SSR-сборкой Vite и рендерит каждый адрес в свой файл: `afisha.html`, `spektakl/simon.html` и так далее, всего 21 страница. В каждую вписываются заголовок, описание, canonical, Open Graph и JSON-LD (`PerformingArtsTheater`, `TheaterEvent` с ценами, `BreadcrumbList`). Тексты для них в `src/seo/meta.ts`.

Caddy отдаёт готовый файл по адресу: `try_files {path} {path}.html /index.html`.

`sitemap.xml` и открытый `robots.txt` появляются, только если в админке заполнен «Адрес сайта» (`settings.siteUrl`). Пока поле пустое, страницы получают `noindex`, а `robots.txt` закрывает всё. Так временный адрес не попадает в поиск. При переезде на домен поле нужно заполнить, а коды Яндекс Вебмастера, Google и номер Метрики вписываются в тех же настройках.

Ограничение пререндера: компонент не должен трогать `window` и `document` во время рендера. Окна, которые выносятся в `body`, идут через `src/lib/toBody.ts`. Из готового HTML вырезается `opacity: 0`, который анимации ставят до появления.

Пререндер работает только при сборке с корня (`VITE_BASE=/`). Без переменной Vite собирает под старый подпуть GitHub Pages и пререндер пропускает.

## Админка

Decap CMS, страница `/admin`. Правки сохраняются не в GitHub, а на тот же сервер:

```
браузер → Caddy (пароль) → /admin/api → decap-server :8081 (git-режим)
                                              ↓ коммит в /opt/kluch/src
                              kluch-rebuild.path замечает коммит
                                              ↓
                rebuild.sh: уменьшение фото, сборка, пререндер → /opt/kluch/site
```

Сайт обновляется за 10–20 секунд после сохранения. Фото больше 2400 px уменьшаются при сборке. Кто что правил: `git log` в `/opt/kluch/src`. Откат: `git revert`, сайт пересоберётся сам.

Вся админка описана в `public/admin/config.yml`. Ошибка в этом файле ломает её целиком, а проверки при сборке пока нет. После правки конфига стоит открыть админку локально: `npm run cms:server` и `npm run dev`, затем `http://localhost:5173/admin/index.html`.

## Афиша с Билетона

Директор заводит показы на Билетоне. API у Билетона нет, но страница общего виджета театра (`settings.ticketsWidgetUrl`) содержит JSON со всеми сеансами: название, возраст, дата, ссылка на покупку, постер. Поддержка Билетона разрешила его читать.

Каждый час `deploy/cms/bileton-sync.sh` запускает `sync-bileton.mjs`:

- добавляет и обновляет показы в `afisha.json`, будущие даты, которых нет на Билетоне, убирает;
- название вида «Спектакль «…»», которого нет в репертуаре, заводит новым спектаклем;
- если виджет не загрузился, афишу этого спектакля не трогает;
- сохраняет изменения коммитом «Афиша обновлена с Билетона», как правку из админки;
- пишет итог в `bileton-status.json`, а бот присылает письмо о новых спектаклях и ошибках.

Прошедшие показы остаются 90 дней (на них опирается просьба оставить отзыв), потом их убирает `prune-afisha.mjs`.

## Бот, чат и заявки

Один сервис на Node.js 24 без фреймворков, база `node:sqlite`. Подробно: [bot/README.md](../bot/README.md).

- `POST /api/chat`: чат с котом на сайте;
- `POST /api/lead`: заявки с форм сайта;
- `POST /api/event`: обезличенные события кота;
- `GET /health`.

Знание бот берёт из `knowledge.json`, который собирается той же сборкой, что и сайт, и перечитывает его раз в 10 минут. Бот не знает ничего, чего нет на сайте. Справочник ответов и список того, на что бот сам не отвечает, правится в админке («Ответы бота», `src/content/bot.json`).

Модель: gpt-oss-120b через OpenAI-совместимый API. Провайдер задаётся тремя настройками (адрес, способ подписи, имя модели), сейчас это Cloud.ru. Около 0,12 ₽ за ответ.

Сервис умеет работать и как Telegram-бот, но с этого сервера Telegram недоступен, поэтому чтение Telegram выключено (`BOT_POLL=0`). Заявки приходят на почту.

Заявка и письмо о ней пишутся одной транзакцией, письма уходят из очереди с повторами до суток. Раз в неделю приходит выгрузка за неделю, в любой момент её можно получить командой `npm run leads`.

Если почта не принимает письмо о заявке, в Telegram всё равно приходит короткое уведомление без имени и телефона (`TG_NOTIFY_TOKEN`, `TG_NOTIFY_CHAT`). База бота копируется каждую ночь (`deploy/backup/`).

## Проверки

```bash
npm run lint
npm run bot:test                     # сервис и логика бота, без сети и без модели
node bot/scripts/eval.mjs --dry      # проверочные диалоги без модели
npm run bot:eval -- --ids=a,b,c      # выбранные диалоги на живой модели (нужен ключ)
```

В `bot/eval/cases.json` 83 диалога. Без модели проходят только те, где отвечает код. Остальные проверяются прогоном на живой модели, их ответы привязаны к датам афиши.

## Выкладка

Источник правды: репозиторий на сервере (`/opt/kluch/src`), потому что туда же коммитят админка и синхронизация с Билетоном. GitHub служит резервной копией.

1. `git fetch server && git merge --ff-only server/master`: забрать правки театра.
2. `git push server master`: пуш сам запускает сборку сайта.
3. Код бота админка не обновляет. После изменений в `bot/` его копируют в `/opt/kluch/app` и перезапускают `kluch-bot` (`bot/DEPLOY.md`). Данные сайта бот берёт с самого сайта при запуске и после каждой сборки.
4. Если менялся `deploy/cms/rebuild.sh`, переустановить его копию в `/opt/kluch/cms/`, а `kluch-site-publish` в `/usr/local/sbin/`.

Секреты лежат только на сервере (`/etc/kluch.env`) и в локальном `.env.bot`, в репозиторий не попадают. Заявки, диалоги и внутренние документы театра (`bot/data/`, `bot/docs/`) в `.gitignore`.
